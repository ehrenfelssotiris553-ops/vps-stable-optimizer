# VPS 机器管家 V2.7.8

给新 VPS 做体检、更新、基础优化和安全加固。所有修改都要你确认；做过的设置有记录，可以全部撤销，也可以只撤销某一项；改 SSH 和防火墙时有防失联保护。安装后输入 `vps` 打开菜单。

支持 Debian 12/13、Ubuntu 22.04/24.04/26.04，独立 systemd 虚拟机，x86_64 / aarch64。请用 root 登录，或先执行 `sudo -i`。不重装系统，不清空机器，不安装 Docker。

2.6 版相对 V2.5.1 的全部改动见 `优化记录.md`；2.6.1 的改动见其中第十二至十四节，2.7.0 的改动见第十五节，2.7.1 的改动见第十六节，2.7.2 的改动见第十七节，2.7.3 的改动见第十八节，2.7.4 的改动见第十九节，2.7.5 的改动见第二十节，2.7.6 的改动见第二十一节，2.7.7 的改动见第二十二节，2.7.8 的改动见第二十三节。

## 怎样开始

用 root 登录 VPS（或先执行 `sudo -i`），运行这一行：

```bash
curl -fsSLO https://raw.githubusercontent.com/ehrenfelssotiris553-ops/vps-stable-optimizer/main/install.sh && bash install.sh
```

安装器会下载主脚本，用内置的 SHA-256 核对无误后才安装，然后打开菜单。安装器只安装菜单工具，不改系统设置；以后输入 `vps` 就能打开菜单。

- **没有 curl 的系统**，用 wget：

  ```bash
  wget -qO install.sh https://raw.githubusercontent.com/ehrenfelssotiris553-ops/vps-stable-optimizer/main/install.sh && bash install.sh
  ```

- **连不上 GitHub 时**（国内机房的 VPS 常见），手动上传：把 `install.sh` 和 `vps-stable-opt.sh` 上传到 VPS 的同一个目录，在该目录运行（从 2.6.1 起主脚本改为不带版本号的这个文件名，两个文件要从同一个版本里取）：

  ```bash
  bash install.sh --local-file ./vps-stable-opt.sh
  ```

- **刚发布新版的几分钟内**，GitHub 的缓存可能让安装器报「SHA-256 校验失败」。这是校验在保护你，不会装上不一致的版本；等 5 分钟再装即可。
- **更新到新版本**：菜单选 14「检查更新」（或 `vps update`），有新版本时确认一下就会更新，不用再复制安装命令；也可以像以前一样再运行一次上面的安装命令。两种方式都会原地替换主脚本，运行记录、配置备份和回退资料都保留；如果已安装的主脚本被手动改过，会停下来，不覆盖。2.6.x 的菜单里没有检查更新，从 2.6.x 升级要用安装命令；2.7.0 的菜单里检查更新是第 12 项。

建议的使用顺序：

1. 在服务商控制台给机器拍一个快照。
2. 不用自己开 tmux：选 2 一键开荒时，会先问「在 tmux 里运行一键开荒吗？」，直接回车就行（没装 tmux 会自动装上）。这样 SSH 断线时开荒不会中断，重新登录输入 `vps` 选 2 就能回到原来的界面。
3. 输入 `vps`，选 1 体检，看处理计划。
4. 选 2 一键开荒。不想逐项考虑时，在「使用推荐设置吗？」直接回车。
5. 按提示重启（以后需要重启时，也可以在菜单里选 8）。
6. 重新登录后输入 `vps`，选 3 做开荒验收。
7. 以后想单独开启或关闭某一项，选 5 单项设置，不用重跑整个开荒。

不想安装也可以直接运行 `bash vps-stable-opt.sh`；这种情况下，你上传的副本不会被菜单里的卸载删除。

## 一键开荒的步骤

所有选择在第 2、3 步一次问完，之后自动执行，期间不需要操作。最后的 SSH 加固和防火墙确认需要你在场（大约 5 分钟），开始前会响铃提醒。

新机第一次开机后，系统通常会先自动更新几分钟。遇到这种情况，脚本会显示“等它结束后继续”并自动等待（最多 10 分钟），不会报错退出。

| 顺序 | 步骤 | 说明 |
| --- | --- | --- |
| 0 | 防断线 | 不在 tmux/screen 里时，先问要不要在 tmux 里运行（回车就是要，没装会自动装上）。之后的体检和开荒都在 tmux 里进行，SSH 断线也不中断；重新登录输入 `vps` 选 2 就能回去。结束后窗口停住，按回车才关闭，所以断线错过的结果也看得到 |
| 1 | 时间同步 | 最先做：系统时间偏差几天，软件更新就会因签名“尚未生效”而失败 |
| 2 | 软件索引与升级计划 | 模拟升级并标出新内核；询问是否使用推荐设置，不用时再分别问是否升级、是否开启自动安全更新 |
| 3 | 开荒选项 | 用推荐设置时只问 SSH 加固、80/443 和 Fail2ban 白名单；否则一次问完：常用工具、vnStat、旧内核清理、自动重启时间、ZRAM、内核安全参数、TCP 缓冲区上限、SSH 保活、优先 IPv4（只在 IPv6 有问题时问）、主机名修复、时区、SSH 加固、80/443、Fail2ban 白名单 |
| 4 | ZRAM | 内存低于 2GiB 且没有 Swap 时自动配约一半内存；2GiB 以上可选配约 1/4 内存（大小和压缩算法可调）。默认用 zstd 压缩，并设 `vm.swappiness=100`、`vm.page-cluster=0`（适合只有 ZRAM 的 Swap；别处设置过的不改）。内核没有 zram 模块时跳过（Ubuntu 云镜像的精简内核就没有） |
| 4（续） | 硬盘 Swap | 内存低于 2GiB、没有任何 Swap、又用不了 ZRAM 时自动建：`/swapfile`，大小约等于内存、最多 2 GiB（可调），系统盘至少留 3 GB。用 systemd 的 swap 单元启用（不改 fstab），排在 ZRAM 后面用。只在 ext4、xfs 上建，容器类虚拟化跳过。有硬盘 Swap 时内存参数用内核默认值 |
| 5 | 系统升级与组件安装 | `apt-get upgrade --with-new-pkgs`：内核更新不会被漏掉，不删包，不跨大版本；可选清理旧内核。失败时停下并说明下一步：软件包停在半安装状态时先运行 `dpkg --configure -a`，否则多半是网络或软件源，过几分钟重来即可 |
| 6 | BBR | 已有其他 TCP 或队列策略就保留，不换内核；系统开机时本来就会设置 BBR + fq 的（例如服务商镜像），不再重复写配置 |
| 7 | 内核网络安全参数 | 可选：不接受 ICMP 重定向和源路由、开启 SYN Cookies 等；IPv6 的重定向按每张网卡设置（只改 all/default 对已有网卡不生效）；不碰 IP 转发，不影响 Docker、WireGuard、代理 |
| 7（续） | TCP 缓冲区上限和调优 | 内存 1 GiB 以上时在推荐设置里（更小的机器默认不做，可以自己选）：按内存把单个连接的收发缓冲上限加大到 16 / 32 / 64 MiB（内存不到 1 GiB / 不到 4 GiB / 更大），跨洲代理、远距离传大文件时单个连接更快。同时打开两个开关：连接空闲后不重新慢启动（`tcp_slow_start_after_idle=0`），以及大包被路上的设备丢掉时自动探测能走的大小（`tcp_mtu_probing=1`）。只提高不降低，最小值和默认值不变；缓冲仍按需分配，内核的 TCP 总内存上限不变；别处设置过的参数不改 |
| 8–10 | 日志限制、TRIM、自动安全更新 | 只在条件满足时处理，已有配置不覆盖。日志限制（系统盘不大于 20GiB 时）：持久日志最多 100 MiB、保留 90 天，内存里的临时日志最多 50 MiB（两个数都能调）；以前版本写的 14 天会改成新的设置。自动安全更新的两项设置只缺一项时补上缺的那项；有人明确写成 `"0"` 的保留不动，并直接告诉你自动安全更新没有开启 |
| 11 | 自动重启时间 | 只有你填了时间才设置：自动安全更新需要重启时，每天在这个时间重启（按服务器的时区；`4:30` 和 `04:30` 都可以） |
| 12 | 时区 | 可选：列出常用时区，输入编号或时区名；直接回车保持不变 |
| 13 | 主机名解析 | 主机名无法解析时可选在 `/etc/hosts` 补上 |
| 13（续） | SSH 保活 | 推荐设置里有：SSH 连接放着不动时每 60 秒检测一次（可调），不会因为路由器丢掉空闲连接而卡死，断网后约 3 分钟清掉死连接。写入 `/etc/ssh/sshd_config.d/00-vps-stable-keepalive.conf`，先让 sshd 检查配置，通不过就撤回；别处已经设置了保活的保持不变 |
| 13（续） | 优先使用 IPv4 | 只在这台机器有公网 IPv6、却连不上软件源的 IPv6 地址、IPv4 又正常时才推荐：这时程序会先试 IPv6，卡一阵才换 IPv4。在 `/etc/gai.conf` 里加一行（`precedence ::ffff:0:0/96  100`），你自己写过 `precedence` 的不改。xray、sing-box 这类用 Go 写的程序不读这个设置，要在它们自己的配置里指定 |
| 14 | SSH 登录加固 | 可选，详见下文 |
| 15 | 防火墙 | 放行 SSH；80/443 按你的选择；开启前列出会被挡住的对外服务（例如 8080 上的网站、WireGuard 的 UDP 51820），回车就一并放行；允许密码登录时 SSH 端口限速（同一 IP 30 秒内连接 6 次会被暂时拒绝），Fail2ban 白名单里的 IP 不受限，多线程传文件也不会被拒；有公网 IPv6 却没开 IPv6 防护时会询问；新开 SSH 窗口能登录才保留（登录成功自动确认）；保留后设为开机自动加载 |
| 16 | Fail2ban | 防火墙确认生效后才配置，只封 SSH 端口；首次封 1 小时，同一 IP 再犯时间加倍（最长 7 天）；可选把当前 IP 加白名单（回车就加；白名单 IP 输错密码不会被封，连 SSH 也不限速） |
| — | 验收与重启 | 结束时逐项核对一遍；需要重启时会问「现在重启吗？」，回答 `y` 才重启 |

## 推荐设置

一键开荒在列出升级清单后会问「使用推荐设置吗？ [Y/n]」，直接回车就是使用。推荐设置包括：

- 升级系统（有可升级的软件包时）；
- 开启自动安全更新（不自动重启整机）；
- 安装常用工具：curl、wget、ca-certificates、vim、htop、unzip、lsof、tmux；
- 启用内核网络安全参数；
- 升级后清理不再需要的旧内核（保留正在运行的和最新的内核；只删 APT 认定可删的旧内核包，其他不再需要的软件包不动）；
- 主机名无法解析时，在 `/etc/hosts` 补上；
- 内存 1 GiB 以上时，加大 TCP 缓冲区上限并打开两个 TCP 开关；
- SSH 保活（每 60 秒）；
- IPv6 有问题（见上表）时，改成优先使用 IPv4。

不在推荐设置里、保持不变的：vnStat、ZRAM（内存不到 2GiB 且没有 Swap 时仍会自动配）、自动重启时间、时区、内存不到 1 GiB 时的 TCP 缓冲区上限，以及只在单项设置里有的连接跟踪容量、禁止 ping。BBR、日志限制、TRIM、时间同步本来就是条件满足时自动处理。

SSH 加固、防火墙放行 80/443 和 Fail2ban 白名单不在推荐设置里，每次都会单独问你（白名单直接回车就是加）。以后想改其中任何一项，用菜单 5「单项设置」。

## 单项设置（`vps item`）

列出每一项和它现在的状态，选一项就能单独开启或关闭，不用重跑整个开荒：

| 项目 | 可以做什么 |
| --- | --- |
| 系统升级、清理旧内核 | 立即执行一次（先模拟并列出清单，再问你） |
| 自动安全更新、BBR、内核网络安全参数、ZRAM、日志空间限制、定期 TRIM、时间同步、主机名解析 | 开启；或关闭（撤销本工具的修改） |
| 更新后自动重启 | 设置每天的重启时间；或取消 |
| 时区 | 修改；或恢复成原来的时区 |
| 常用工具、vnStat | 安装；或卸载（只卸载本工具装的，先模拟） |
| 防火墙 | 开启（要新开 SSH 窗口确认）；临时关闭；撤销本工具的防火墙设置 |
| Fail2ban | 开启（需要防火墙已开启）；或关闭；管理白名单（多个 IP 或网段，随时增删） |
| SSH 登录加固 | 加固；或撤销（恢复密码和 root 登录） |
| 端口管理 | 进入端口管理 |
| TCP 缓冲区上限（第 19 项） | 开启；或关闭（删除配置并恢复原来的运行值）；调整参数；恢复推荐值 |
| 主机名和显示名（第 20 项） | 修改显示名；修改主机名；撤销主机名修改（恢复原来的名字） |
| 硬盘 Swap（第 21 项） | 开启（已有别的 Swap 时先问）；或关闭（先确认可用内存够把 Swap 里的内容挪回来，再停用、删文件）；调整大小；恢复推荐值 |
| 连接跟踪容量（第 22 项） | 开启：把内核能同时记住的连接数调大（每 MiB 内存 64 条，16384 到 1048576 条），已建立连接的记录保留 5 天；只调大不调小，内核原来的值更大时不动。防火墙开着时内核要为每条连接记一条，表满了新连接会被直接丢掉（代理、网站连接多时常见）。另外写 `/etc/modules-load.d/99-vps-stable-conntrack.conf`，让开机时先加载模块，设置才能生效。`vps check` 会显示用了多少，超过 70% 时提醒。关闭：删掉配置、恢复原来的值；调整参数；恢复推荐值 |
| 禁止 ping（第 23 项） | 开启前先说明：它只挡最基础的扫描，代价是服务商和你自己的 ping 监控会把机器当成宕机；IPv4 和 IPv6 都不回应。关闭：恢复原来的设置 |
| SSH 保活（第 24 项） | 开启；或关闭（删掉本工具的配置并重新加载 SSH）；调整间隔；恢复推荐值 |
| 优先使用 IPv4（第 25 项） | 开启前先说明 IPv6 是不是真的有问题（没问题时一般不需要）；或关闭（`/etc/gai.conf` 恢复成原来的样子） |

菜单底部还有：`p` 参数总览，`e` 导出参数，`i` 导入参数，`u` 界面符号（改用纯 ASCII，下次打开生效）。

- **关闭只撤销本工具的修改**：系统原来就有的设置不动。本工具没有改过的项目，会告诉你“本工具没有改过”，不做任何事。
- **临时关闭防火墙**：规则都保留，以后在单项设置里选「开启」就恢复；重启后也保持关闭，排查完记得开回来。撤销则会删掉本工具加的规则。
- **关闭自动安全更新、ZRAM、vnStat**：撤销设置后，还会问是否卸载本工具为它装的软件包（unattended-upgrades、systemd-zram-generator、vnstat），不卸载的话软件包和它的常驻进程会留着。
- **你自己手动改过的项目**（例如手动执行过 `ufw disable`）：一键开荒和单项设置都照常执行，不会因此跳过；以后撤销时，一律恢复成本工具第一次运行前的样子。
- 单项设置同样会先备份，记录写进操作记录；只有这次做了系统升级、需要重启时，结束后才会问你。

### 参数（`vps params`）

能调的项目有「调整参数」和「恢复推荐值」。一键开荒不会多问：每个参数默认是**自动**，用按这台机器算出来的推荐值，每次用时重新算，所以加了内存、换了硬盘以后会跟着变。你调过的值会一直保留，重跑一键开荒也不改，直到你选「恢复推荐值」。

- **调整时**：先显示现在的值、本机推荐值和推荐理由。值不在允许范围内会要你重输；值比较偏激的，先说明后果，你确认后才用。这一项已经开启，就马上按新值重新应用；还没开启，就等开启时再用。
- **验收会提醒**：生效的值和现在该用的值不一样时（例如加了内存后推荐值变大了，或者导入了参数还没应用），`vps check` 会显示「⚠ 可更新」并告诉你怎么更新，不算失败。
- **参数总览**：`vps params`（或单项设置里选 `p`）一屏列出所有参数现在的值、本机推荐值和理由。
- **复制到别的机器**：`vps params export` 输出几行文字。在另一台机器上运行 `vps params import`，把这几行粘贴进去（以空行结束），或者用 `vps params import 文件`。导入前逐行检查，不认识的行、超出范围的值都会跳过；你确认后才保存，已开启的项目可以马上按新值应用。`auto` 表示用那台机器自己的推荐值。
- 参数保存在 `/var/lib/vps-stable-opt/params`，卸载本工具时会一起删除；需要的话先导出。

目前能调的参数（后续版本会陆续加上 Fail2ban 等）：

| 参数 | 范围 | 本机推荐值 |
| --- | --- | --- |
| TCP 缓冲区上限 | 4–256 MiB | 内存不到 1 GiB 用 16，不到 4 GiB 用 32，更大用 64 |
| ZRAM 大小（占内存） | 10–150% | 内存不到 2 GiB 用 50，更大用 25 |
| ZRAM 压缩算法 | zstd、lz4、lzo-rle | zstd（压缩率最高）；CPU 很弱又常用到 ZRAM 时可选 lz4 |
| 硬盘 Swap 大小 | 128–8192 MiB | 约等于内存，最多 2048 |
| 日志空间上限 | 16–4096 MiB | 100（内存里的临时日志用它的一半，至少 16） |
| 日志保留天数 | 1–3650 天 | 90：出了问题（包括可能的入侵）能往回查一个季度 |
| 连接跟踪上限 | 16384–4194304 条 | 每 MiB 内存 64 条，最多 1048576（每条约 320 字节，不用时不占） |
| 已建立连接的保留时间 | 2–720 小时 | 120（内核默认 5 天）；最短 2 小时，再短会误删还活着的空闲连接 |
| SSH 保活间隔 | 15–600 秒 | 60 |
| 每天自动安全更新的时间 | `HH:MM`（24 小时制） | 06:00（系统默认，随机推迟最多一小时）；改了才写 `/etc/systemd/system/apt-daily-upgrade.timer.d/50-vps-stable-time.conf` |
| 常用工具清单 | 1–30 个软件包名，用空格隔开 | `curl wget ca-certificates vim htop unzip lsof tmux`；去掉 tmux 时会提醒：断线防护要用它 |

- **ZRAM 改了大小或算法**：正在使用的 ZRAM 不能安全地直接改，新设置在重启后生效；重启之前 `vps check` 显示「⚠ 待重启」。
- **硬盘 Swap 改了大小**：先确认可用内存够把 Swap 里的内容挪回来，再按新大小重建；内存不够时保持原样，稍后再试。

调低上限时，工具会拿本工具第一次运行前的原值比较（这时正在生效的是工具自己设的值），新上限不再需要调大的参数会马上恢复成原值；上限不比原值大时，工具的配置整个删掉、参数恢复原值。

### 主机名和显示名

- **显示名**：只用在本工具的菜单里（以后的通知也用），可以写中文，最多 24 列（一个汉字算两列）；不改系统的主机名。菜单标题栏显示成「显示名（主机名）」。
- **修改主机名**：只能用小写字母、数字和连字符，最长 63 位。同时改两处：开机读的名字（`/etc/hostname`）和正在用的名字，不用重启，SSH 也不会断。新名字解析不了时，在 `/etc/hosts` 加一行 `127.0.1.1 新名字`，免得 sudo 报 `unable to resolve host`；再改一次名时，工具上次加的那行会删掉。
- **重启后不会被改回去**：多数服务商镜像里的 cloud-init 每次开机都会把主机名设回服务商后台的名字。工具会写 `/etc/cloud/cloud.cfg.d/99-vps-stable-hostname.cfg` 让它保留新名字。有些镜像（Debian 的）由 cloud-init 每次开机重写 `/etc/hosts`，这时工具让 cloud-init 马上按新名字重写一次。`vps check` 会检查重启后名字还在、能解析。
- **撤销**：恢复原来的名字，删掉 cloud-init 的设置和工具为新名字加的 hosts 行（由 cloud-init 管 hosts 的，让它按原来的名字重写），开荒时为解析主机名加的那行不受影响。
- 监控面板、集群之类按主机名认机器的，要自己同步。

只会在当前大版本内升级，不会升到新的系统大版本（例如 Debian 12 → 13、Ubuntu 24.04 → 26.04）。软件源里写的是 `stable` 这类别名时会被拦下，并告诉你怎么改成版本代号。Debian 云镜像的软件源写成 `mirror+file:///etc/apt/mirrors/…` 时，会读取那个镜像列表，里面全是官方地址就按官方源检查。

## SSH 登录加固

1. **管理员账户（推荐）**：用 root 登录时，可以新建一个普通管理员账户（加入 sudo 组并设置密码）。已经在用 sudo 账户登录时，可以直接选择禁止 root 直接登录。
2. **公钥登录被服务商关掉时先开启**：有些镜像在 `/etc/ssh/sshd_config` 里写了 `PubkeyAuthentication no`。这时会显示是哪个文件哪一行，并问你要不要先开启公钥登录：新增 `/etc/ssh/sshd_config.d/00-vps-stable-pubkey.conf`（原配置文件不改），只是多一种登录方式，密码登录照常可用。撤销时会删掉这个文件，公钥登录回到原来的关闭状态。
3. **导入公钥**：公钥以目标账户自己的身份写入，并且会先检查家目录的归属和权限。还没有密钥时，会告诉你怎么在自己电脑上生成（`ssh-keygen -t ed25519`）。
4. **确认密钥登录**：新开一个窗口用密钥登录。如果要禁止 root 登录，还要在那个窗口里运行一次 `sudo true`。脚本会在系统日志里确认这两件事都发生过；找不到记录时，会分别问你是否确定已经成功（回答 `y`）。sudo 没有确认时，只关闭密码登录，不禁止 root 登录。
5. **控制台登录检查**：服务商的 VNC 控制台只能用密码登录。如果目标账户和 root 都没有可用的密码，会提示你当场设置一个；不设置就要输入 `NOCONSOLE` 才能继续。
6. **写入配置**：写入 `/etc/ssh/sshd_config.d/01-vps-stable-keyonly.conf`，包括：
   - 关闭密码登录；
   - 可选禁止 root 登录；
   - `MaxAuthTries 4`；
   - `LoginGraceTime 30`；
   - `X11Forwarding no`。

   空闲连接的保活从 2.8.0 起是单独的一项（SSH 保活，第 24 项），不再写在这里；以前版本写的 `ClientAliveInterval 300` 会被 SSH 保活的设置盖过。

   写入后会检查每一项确实生效；被更早的配置覆盖的，会自动撤销并告诉你是哪一项。
7. **防失联确认**：先启用自动撤销计时器，再请你新开一个窗口用密钥登录。登录成功后脚本会自动确认；没有自动确认时，回到原来的窗口输入 `CONNECTED`。180 秒内没有确认就恢复原来的设置；脚本万一中断，240 秒时计时器也会自动恢复。

不改 SSH 端口。导入的公钥和新建的账户在回退时都会保留。

## 端口管理

菜单选 4，或者直接用命令：

```bash
vps port open 8080
```

```bash
vps port open 443-600 udp
```

```bash
vps port open 3306 tcp from 203.0.113.5
```

```bash
vps port close 8080
```

```bash
vps port list
```

- **端口写法**：支持 `8080`、`443-600`、`8080,9000-9100`。命令行不写协议时默认 both（TCP+UDP）。
- **自动拒绝**：会拒绝一次放行全部端口，也会拒绝关闭 SSH 端口或包含它的端口段。
- **命令写错就停下**：`from` 后面没写 IP、协议写错、多出看不懂的参数时直接报错，不会按「所有人」放行。
- **只关一种协议**：不写协议的规则（例如 `ufw allow 18081`）同时放行 TCP 和 UDP。只关其中一种时，会先单独放行另一种，再删除原来那条，另一种协议不受影响；单独放行失败时原规则保持不变。所以 `vps port close 22 udp` 只关 UDP，SSH 的 TCP 照常放行。单独放行的规则会排到最后：原规则后面如果还有可能挡住它的拒绝或限速规则，拆分会改变实际效果，这时不改动，并告诉你怎么手动处理。
- **高危端口提醒**：数据库、管理类端口（MySQL、Redis、MongoDB、Docker API、RDP 等）要对所有人开放时，会提醒并再确认一次，并建议改成只允许你自己的 IP。
- **大范围确认**：一次放行超过 1000 个端口时会再确认一次。
- **Docker**：检测到 Docker 时会提醒：用 `-p` 发布的容器端口会绕过 UFW。
- **回退时保留**：用端口管理放行的业务端口，在撤销设置时会保留。

## 检查更新（`vps update`）

菜单选 14，或者直接用命令 `vps update`：

- **先看有没有新版本**：显示本机版本和 GitHub 上的最新版本，一样就告诉你「已经是最新版本」，什么都不改。
- **有新版本时问你一次**：回车就更新；更新只替换本工具自己的程序，不改动任何系统设置，运行记录、配置备份和回退资料都保留。
- **和一行安装命令同样安全**：从本仓库 `main` 分支用 HTTPS 下载 `install.sh` 和主脚本，主脚本必须和 `install.sh` 里写死的 SHA-256 一致，再由 `install.sh` 原地安装。刚发布的几分钟里两边可能对不上，这时只提示稍后再试，不会更新。
- **不会降级**：本机版本比 GitHub 上的还新时不做改动。
- **更新后**：直接打开新版本的菜单，不用重新输入 `vps`（新脚本读不通时菜单退出，并提示重新运行安装命令）。

## Fail2ban 封禁记录（`vps bans`）

菜单选 6，或者直接用命令 `vps bans`：

- 正在封禁的 IP（每个 IP 什么时候封的、什么时候解封）、每次封多久；
- 封禁时长：首次封多久、同一 IP 再犯是否加倍；
- Fail2ban 这次启动以来识别出的失败登录次数和封禁次数；
- 你当前登录用的 IP 有没有被封、白名单里有哪些地址；
- 最近 20 条封禁和解封记录（读 Fail2ban 的日志；它写进系统日志时就读系统日志）。

有 IP 正被封禁时，可以输入其中一个解封（要再确认一次）；只接受列表里的单个地址。

### 白名单

单项设置 →「Fail2ban 防爆破」→ 3 管理白名单：

- 白名单里的地址输错密码也不会被封。可以放多个（最多 20 个），单个 IP 或网段都行：IPv4 网段最大到 /16，IPv6 最大到 /32，比 /24（IPv6 是 /48）大时会先提醒你，因为网段里的任何人都不会被封。
- 添加时直接回车就是加你现在连进来的 IP；这个 IP 正好被封着的话，会顺便问你要不要解封。删除你现在的 IP 要再确认一次。
- 改动马上生效：规则文件改好（重启后还在），正在运行的 Fail2ban 也直接加上或去掉，不用重载，现有的封禁不受影响。
- **SSH 免限速跟着同步**：防火墙对 SSH 限速时，白名单里的每个单个 IP 连 SSH 都不限速（网段只防封，不免限速）；删掉一个地址时，只删本工具为它加的那条免限速规则，你自己加的规则不动。
- 换了宽带、IP 变了，记得来这里改。

## 重启服务器（`vps reboot`）

菜单选 8，或者直接用命令 `vps reboot`：

- **先说明需不需要重启**：装了新内核还没生效、系统提示需要重启，或者目前不需要重启。
- **这两种情况下不会重启**：
  - 防火墙或 SSH 加固的防失联确认还没结束：重启会让保护计时器失效，没确认的修改就会被永久保留。先回到那个窗口完成确认，或者等计时结束。
  - 有程序正在安装或更新软件：会先等它结束（最多 10 分钟），还没结束就不重启，免得损坏软件包。
- **回答 `y` 才重启**：所有 SSH 连接会断开，通常一两分钟后可以重新登录。重启后输入 `vps` 选 3 做开荒验收。

## 开荒验收（`vps check`）

脚本会记下每个模块在开荒时的结果，验收时逐项核对：

- **✅ 生效**：按预期在工作。
- **❌ 未生效**：做了，但现在没起作用，会说明原因和处理方法。
- **➖ 未处理**：按计划本来就没做，或者后来撤销了（会写明「已撤销」）。
- **❓ 无法确认**：缺少条件判断，例如内核或容器读不到某个参数。
- **⏳ 待重启**：要重启后才生效，例如开荒时装了新内核、还没重启。重启后再验收就会变成 ✅。

验收会核对开荒做过的每个模块：
- 系统：内核、BBR、内核安全参数、TCP 调优、ZRAM、硬盘 Swap、时间同步、日志限制、TRIM；
- 网络：连接跟踪容量（还会显示用了多少，超过 70% 时提醒）、禁止 ping、SSH 保活（sshd 实际生效的间隔）、优先 IPv4（解析结果确实是 IPv4 在前）；
- 更新：自动安全更新、自动重启时间；
- 工具和设置：常用工具、流量统计、时区、主机名；
- 安全：SSH（包括 root 是否真的不能直接登录）、防火墙、Fail2ban。

其中几项看得更严：
- 防火墙除了现在开着，还要设为开机自动加载（`ufw.service`），否则重启后就没有防火墙；
- Fail2ban 的封禁要靠防火墙执行，防火墙没运行就算未生效；
- 系统盘不支持 TRIM（`lsblk` 的 DISC-MAX 为 0）时显示为未处理，不算生效。

有项目「未生效」时，`vps check` 的退出码是 3（没有未生效项目时是 0），方便脚本判断。

此外还会检查：
- 开荒后是否重启过；
- 当前 SSH 连接实际用的拥塞算法；
- 失败的服务（写出服务名）、DNS 解析。SSH、防火墙、Fail2ban、时间同步、vnStat、自动更新、ZRAM、日志服务这些失败算「✖ 未生效」；其他服务失败只显示「⚠ 注意」，列在「需要你看一下」里，不影响结论和退出码；
- 有没有装 Docker。

报告先给结论：几项正常、几项未生效，再列出需要你看一下的项目（未生效、待重启、无法确认、可更新、提醒），最后是每一项的详细结果。报告保存在 `/var/lib/vps-stable-opt/logs/`，是纯文字，只保留最近 10 份。可选的 Fail2ban 实弹测试，用专门留给测试的 IP 地址模拟封禁再解封，不需要你去登录。

## 性能体检和资源占用

都只读，不改任何设置。

**性能体检（`vps perf`，菜单 1 → 2）**：用 3 秒采样，加上开机以来的统计，逐项给出 ✔ 正常或 ⚠ 注意，并说明是什么意思：

- CPU 被抢（steal）：同一台宿主机上别的机器在抢 CPU（超卖），超过 5% 提醒；
- 等硬盘（iowait）、负载（和核数比）、内核报告的 CPU、内存、硬盘压力（PSI，过去 1 分钟）；
- 可用内存、每秒换页数（频繁用 Swap 会明显变慢）；
- TCP 重传比例（线路丢包）、连接跟踪表用了多少；
- 系统盘的空间和文件数（inode）。

偶尔一次的 ⚠ 不代表有问题，长期这样再处理。

**资源占用一览（`vps resources`，菜单 1 → 3）**：列出正在运行的常驻服务各占多少内存、开机以来用了多少 CPU，能不能关、关了失去什么（例如 Fail2ban 关了就没有防爆破）；ZRAM 存了多少数据、实际占多少内存；防火墙里的封禁规则有多少条，超过 300 条时提醒：每次封禁、解封都要重新加载规则，攻击很多时会占不少 CPU。

## 体检里新增的安全检查

- **公钥清单**：列出 root 和所有普通账户的 `authorized_keys` 公钥指纹，帮你发现镜像或服务商预置的公钥。
- **Docker**：检测到 Docker 时提醒容器端口会绕过防火墙。
- **软件包中断**：软件包处于中断状态时，告诉你用 `dpkg --configure -a` 修复。

## 怎样回答问题

大多数问题用 `y` 或回车回答：

- **`[Y/n]`**：直接回车表示「做」。用于推荐的、风险低的选择：使用推荐设置、系统升级、自动安全更新、内核网络安全参数、主机名修复、Fail2ban 白名单、开启防火墙时一并放行正在使用的服务。
- **`[y/N]`**：直接回车表示「不做」，要输入 `y` 才做。用于开始修改、关闭端口、重启、撤销、卸载软件包等。

只有三处要输入单词。提示里会写出要输入什么，区分大小写；输成小写时会提醒你要用大写：

| 单词 | 什么时候要输 |
| --- | --- |
| `CONNECTED` | 开启防火墙或加固 SSH 后，新开一个 SSH 窗口登录：登录成功通常会自动确认，不用输入。没有自动确认时，回到**原来的窗口**输入（新窗口里不用输入任何东西）。输错或输成小写会提示你重输；新窗口登录失败就在原窗口输入 `n`，立即恢复；180 秒内没有确认，也会自动恢复原来的设置。 |
| `NOCONSOLE` | 没有控制台密码时，仍要关闭 SSH 密码登录（不推荐：SSH 出问题时控制台也进不去）。 |
| `UNINSTALL` | 卸载本工具，会删除全部记录和备份。 |

## 撤销设置与卸载

| 操作 | 工具、记录、备份 | 软件 | 优化配置和效果 |
| --- | --- | --- | --- |
| 撤销本工具的设置 | 保留 | 保留；可选卸载本工具新装的包 | 恢复成本工具第一次运行前的样子（例外见下文） |
| 卸载本工具 | 删除 | 保留 | 保留 |

菜单选 12（或 `vps rollback`）会先列出和本工具第一次运行前不一样的项目，再让你选：

- **1. 全部撤销**：按安全的顺序（先 Fail2ban，再防火墙，再 SSH 和其他设置）全部恢复，最后可选卸载本工具新装的软件包。
- **2. 只撤销某一项**：从列表里选一项，例如只撤销 BBR，其他设置不动。

单项设置里的「关闭」和这里的「只撤销某一项」是同一套逻辑。

撤销设置时：

- **一律恢复原样**：本工具记录过的设置，撤销时都恢复成本工具第一次运行前的样子，不管中间是谁改的——你后来手动改过的也一样。
- **只放宽访问**：只会关闭防火墙、恢复密码和 root 登录，不会把你锁在外面。关闭防火墙后会提醒你，所有监听的端口都已直接暴露。
- **防火墙按规则回退**：只删除本工具自己加的规则（包括开启防火墙时一并放行的服务端口、白名单 IP 的 SSH 免限速规则），再恢复默认策略、IPv6 开关和防火墙开关。你后来放行的端口、Fail2ban 的封禁记录都不受影响。
- **Fail2ban**：先解除本工具封禁的 IP，再删除本工具的规则和动作文件；原来就有的 Fail2ban 会按它自己的配置重新加载。
- **内核安全参数**：删除配置文件，并把运行中的参数（包括每张网卡的 IPv6 重定向设置）恢复为原来的值。
- **TCP 缓冲区上限**：删除配置文件，并把四个缓冲参数恢复为原来的运行值。
- **ZRAM**：删除配置和配套的内存参数并关闭 ZRAM。`systemd-zram-generator` 软件包自带默认配置，只要它还在，ZRAM 很快就会按约一半内存重新开启，所以撤销时会问是否卸载这个本工具装的软件包：卸载后 ZRAM 保持关闭；不卸载则如实告诉你 ZRAM 会继续开启。
- **`/etc/hosts`**：这个文件你和系统都会改，所以只删除本工具加的那一行主机名，其他行不动。
- **连接跟踪、禁止 ping**：删除配置文件，并把运行中的值恢复为原来的值。
- **SSH 保活**：删除配置文件并重新加载 SSH；**优先 IPv4**：`/etc/gai.conf` 恢复成原来的样子（原来没有就删掉）。
- **其他设置**：BBR、ZRAM、日志限制、自动更新（包括改过的更新时间）、自动重启时间、时间同步、TRIM、时区也都恢复成原来的样子。
- **卸载软件包需模拟确认**：卸载本工具新装的软件包前会先模拟；会连带删除原来就有的软件时不执行。为防断线自动装上的 tmux 也算本工具新装的。
- **撤销不了的部分**：
  - 系统升级（软件包不会降回旧版本）、新内核、已经清理的旧内核；
  - 已执行的 TRIM 和已经校准的系统时间（时间同步的开关本身会恢复）。
- **有意保留的部分**：
  - 导入的 SSH 公钥、新建的管理员账户和它的密码（删掉可能把你锁在外面）；
  - 用端口管理放行的业务端口；
  - 新装的软件包（可选卸载，只卸本工具装的）。卸载时连同配置一起删除（purge），回到装之前的样子，Fail2ban 的封禁记录也会删掉。以下情况只卸程序、保留配置：
    - 这些配置和软件包装上时不一样（可能是你改过的，包括 UFW 里还存着的规则）：会先列出来问你要不要一起删；
    - 本工具第一次运行前，这个软件包就留有配置；
    - 恢复记录是 2.8.0 之前的版本做的（它们没有记下装之前哪些软件留有配置）。
  - 防火墙不会被自动重新打开：如果它原来开着、后来被关掉了，撤销会提示你手动执行 `ufw enable`。

  需要整机还原时，请用服务商快照。

**卸载会删除备份。** 删除后，即使重新安装也无法可靠回退。需要的话，先把备份保存到自己的电脑。

## Ubuntu 24.04 说明

已在一台 Ubuntu 24.04 云服务器上完整实测（2.7.4）。和 Debian 不同、本工具已经处理的地方：

- **`/var/log` 归 `root:syslog`、组可写**：本工具的运行日志放在只有 root 能写的 `/var/lib/vps-stable-opt/logs/`，不放在 `/var/log` 下。
- **系统自带 `/etc/sysctl.d/10-bufferbloat.conf`（fq_codel）**：没被改过时算系统默认值，不会因此跳过 BBR；改过的照旧当作你自己的设置保留。
- **云镜像的精简内核没有 zram 模块**：ZRAM 自动跳过并说明原因；本工具不会为此额外安装几百 MB 的 `linux-modules-extra`。
- **SSH 按需启动（ssh.socket）**、**系统自带 UFW 和自动更新**：SSH 加固、防火墙、撤销都按原有设置正确处理，系统自带的软件包不会被卸载。

## Ubuntu 26.04 说明

Ubuntu 26.04 LTS（resolute，标准维护到 2031 年 5 月）默认做了几处改动，本工具都已考虑：

- **Rust 版 coreutils（uutils）**：`ls`、`stat`、`sort` 等基础命令换成了 Rust 实现。本工具每次启动都会先做一次基础命令自检（`mktemp`、`install`、`stat`、`sort -V`、`sha256sum`、`df`、`readlink`、`cp -p`、`mv` 等）。行为和预期不一致时直接停止，不做任何修改，并提示可以用 `apt install coreutils-from-gnu` 换回 GNU 版本。
- **sudo-rs**：默认 sudo 换成了 Rust 实现。SSH 加固时，脚本会在系统日志里找 sudo 的记录；如果日志格式不同而找不到，会改为问你是否确定 sudo 可用。
- **chrony**：默认用 chrony 做时间同步。已有可用的时间同步时，本工具保持不变，不会再装 systemd-timesyncd。

这几处还需要在真实的 26.04 机器上确认，见 `优化记录.md`。

## 固定目录

| 内容 | 位置 |
| --- | --- |
| 调用命令 | `/usr/local/bin/vps` |
| 主脚本 | `/usr/local/lib/vps-stable-opt/vps-stable-opt.sh` |
| 运行状态、回退基线（`restore-v2`）、开荒结果（`modules`） | `/var/lib/vps-stable-opt/` |
| 每次运行的配置备份 | `/var/backups/vps-stable-opt/` |
| 运行日志（开荒保留最近 9 份，端口操作单独保留 20 份）、验收报告 | `/var/lib/vps-stable-opt/logs/`（2.7.4 以前在 `/var/log/vps-stable-opt/`，卸载时一起删除） |

数据目录必须归 root 所有，路径里不能有符号链接，其他用户不能写入，不满足时会直接停止。已经有别的 `vps` 命令时，安装也会停止，避免覆盖。

每次开荒、单项设置、防火墙或 SSH 加固都会新建一份运行记录和配置备份。只保留第一次（工具运行前的原始配置）和最近 20 次，更早的会自动删除；撤销用的回退基线（`restore-v2`）不受影响。

## 会不会一直占用内存

本工具只在你运行 `vps` 时工作，退出后不留任何后台进程、定时任务或开机启动项。唯一的例外是开启防火墙和 SSH 加固时的防失联计时器：最多存在 4 分钟，确认或到期后自动消失。

后台常驻的是你选择开启的系统服务本身（以下是常见的大致范围）：

| 服务 | 常驻内存 |
| --- | --- |
| Fail2ban | 约 20–50 MB，最大的一项（实测约 28 MB） |
| 自动安全更新 | 约 10–25 MB（实测常驻约 22 MB）；每天更新的那几分钟会多占一些，之后释放 |
| vnStat | 1–4 MB |
| ZRAM | 平时几乎不占，内存紧张时才使用 |
| 防火墙、BBR、内核参数、日志上限、TRIM | 没有常驻进程 |

日志上限还会把内存里的临时日志限制在持久日志上限的一半（默认 50 MiB）。用 `vps resources` 可以直接看到这台机器上每个常驻服务实际占了多少（见下文）。想自己核对，可以运行 `ps -eo rss,comm --sort=-rss | head -15`。实测（Debian 13，715 MiB 内存）：开荒前系统已用约 175 MB，开荒后约 201 MB。

## 测试与验证状态

在一台可以重置的 Linux 测试 VPS 上，用 root 下载整个仓库（没有 git 就先 `apt-get install git`）：

```bash
git clone https://github.com/ehrenfelssotiris553-ops/vps-stable-optimizer.git && cd vps-stable-optimizer
```

然后运行：

```bash
bash tests/run-all.sh
```

这些测试只把主脚本里的函数单独提取出来，配合临时文件和模拟命令运行，不会执行真正的优化。通过后，再按「体检 → 开荒 → 重启 → 验收 → 单项设置 → 端口管理 → 只撤销某一项 → 全部撤销 → 卸载」的顺序做一遍真机验收。

### GitHub 上的自动测试

每次推送，GitHub 都会在用完即删的临时机器上自动测试，不碰任何真实的 VPS（配置在 `.github/workflows/`，用到的脚本在 `tests/ci/`）。三层每周日北京时间凌晨 3 点也会各跑一次：代码没改，系统的软件包更新也可能让工具出问题，这样能比自己的 VPS 更早发现。

| 层 | 内容 | 什么时候跑 |
| --- | --- | --- |
| 第 1 层（tests） | ShellCheck 0.11.0，主脚本和安装器不允许有任何提示；全部测试以 root 身份分别在 Debian 12、Debian 13、Ubuntu 22.04、24.04、26.04 里跑 | 每次推送、每周 |
| 第 2 层（real-run） | 在 Ubuntu 22.04、24.04、26.04 和 ARM 的临时虚拟机上真跑：安装、体检、一键开荒（自定义）、验收；单项设置逐项关闭（检查回到系统原样）再开启（检查生效）；端口管理（菜单和命令行放行、限定来源 IP、关闭）；再验收、全部撤销（含卸载软件包）、卸载，每一步之后检查留下的状态。每台机器各跑两遍：一遍全新安装，一遍先用上一个发布版开荒、再原地升级到新版继续。另有两种机器：按「最不推荐」回答（不用推荐设置、可选项全部不要、放行 80/443、不加白名单），检查拒绝的项目确实原样未动；装着 Docker、有容器开放端口的机器，检查防火墙按设计保留、容器在开荒、Docker 重启和撤销后都能访问、能上网 | 每次推送、每周 |
| 第 3 层（vm-run） | 在临时虚拟机里再用官方云镜像开 512 MiB 的 Debian 12、13 和 Ubuntu 22.04、24.04、26.04 虚拟机，从外面 SSH 登录：推荐设置开荒、新窗口登录自动确认、白名单 IP 连续登录不被限速、重启后验收、在 tmux 里开荒时断线再回来、开荒中途按 Ctrl+C 再重新开荒；从外面验证真实效果（没放行的端口连不上、放行后能连、关闭后又连不上；第二块网卡上的「陌生 IP」连续输错密码真的被封，`vps bans` 列出带时间的记录并在那里解封）；SSH 加固真做一遍（中途断线后自动恢复原设置；再做一遍：只允许密钥、新建 sudo 管理员、禁止 root 登录，重启后仍然有效）；最后由管理员全部撤销、卸载。另用 Debian 12、Ubuntu 22.04、24.04 的首发镜像各跑一遍：要装几年的更新、换内核，开荒在 tmux 里进行，系统升级途中断开 SSH，重新登录后回去做完 | 推送到 `release/` 开头的分支时、每周，或手动触发 |
| 发布后（release-smoke） | 推送到 main 后，等 GitHub 实际提供新版本，再用 README 里的一行命令安装，并从上一个发布版用 `vps update` 在线升级 | 推送到 main 时、每周 |

第 2、3 层的结尾都会把撤销和卸载之后的机器和安装之前逐项对比：全部内核参数、软件包、开机服务、/etc 下每个文件的校验值、防火墙规则、swap、用户等。每处不同都必须说得清原因（例如加载过的内核模块、系统升级带来的包），否则判失败；卸载软件包后留下的配置之类，会作为黄色警告列出。工具报告的事实（内存、硬盘、SSH 端口、ZRAM 大小、当前连接是否在用 BBR 等）也会和机器本身的数据对照；全新机器上的健康检查不允许有误报。

交互的问题由 `tests/ci/answer.exp` 按 `tests/ci/rules/` 里的规则回答；遇到规则里没有的问题会直接判失败，不会卡住。`tests/consistency-tests.sh` 检查每个由工具管理的文件和设置都接进了备份、撤销、验收和单项设置，以后新功能漏接一处就会失败。

本工具在一台 Debian 13 测试 VPS 上跑过三轮完整流程，发现的问题都已修复（见 `优化记录.md` 第十一、十二、十五节）；其他系统还没有在真机上验证，具体见「验证状态」一节。

## 发布新版本

仓库地址：https://github.com/ehrenfelssotiris553-ops/vps-stable-optimizer

`install.sh` 里的 `RELEASE_BASE_URL` 指向本仓库 `main` 分支的原始文件；换仓库或分支时要同步修改。已经装过的机器重新运行安装命令就会原地更新到新版本。

版本号只写在主脚本的 `SCRIPT_VERSION` 一处（帮助和菜单标题会显示它），以及 README 标题和 `install.sh` 的说明文字；文件名不带版本号，发布新版本时不用改名。安装目录和数据目录里的归属标记（`:2.6`）表示 2.6 这一代的数据格式，小版本升级时不要改，否则已安装的机器会拒绝原地更新。

安装器会用内嵌的 SHA-256 核对主脚本，所以每次修改主脚本后都要：

1. 重新计算主脚本的 SHA-256，填进 `install.sh` 里的 `EXPECTED_SHA256`。
2. 重新生成 `SHA256SUMS`：

   ```bash
   sha256sum -b .gitattributes README.md 优化记录.md install.sh tests/*.sh tests/ci/*.sh tests/ci/*.py tests/ci/answer.exp tests/ci/rules/*.rules .github/workflows/*.yml vps-stable-opt.sh > SHA256SUMS
   ```

3. 提交并推送。主脚本和 `install.sh` 必须在同一次推送里更新，否则新装的机器会校验失败（安装会停止，不会装错）。
