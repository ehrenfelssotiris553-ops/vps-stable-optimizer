# VPS 机器管家 V2.6.0

给新 VPS 做体检、更新、基础优化和安全加固。所有修改都要你确认；做过的设置有记录，可以全部撤销，也可以只撤销某一项；改 SSH 和防火墙时有防失联保护。安装后输入 `vps` 打开菜单。

支持 Debian 12/13、Ubuntu 22.04/24.04/26.04，独立 systemd 虚拟机，x86_64 / aarch64。请用 root 登录，或先执行 `sudo -i`。不重装系统，不清空机器，不安装 Docker。

本版相对 V2.5.1 的全部改动见 `V2.6.0-优化记录.md`。

## 菜单

```text
 1. 给机器做体检（只检查，不修改）
 2. 一键开荒（更新系统并优化机器）
 3. 单项设置（逐项开启或关闭某一项）
 4. 设置防火墙和 SSH 防爆破
 5. SSH 登录加固（只允许密钥登录，可选新建管理员并禁止 root 直接登录）
 6. 端口管理（放行 / 关闭端口）
 7. 开荒验收（检查优化是否真的生效，适合重启后）
 8. 查看操作记录和配置备份
 9. 撤销本工具的设置（全部或只撤销某一项）
10. 卸载本工具，保留优化效果
11. 重启服务器（先说明是否需要重启，确认后才重启）
 h. 查看使用说明
 0. 退出
```

每一项也可以直接用命令打开：`vps plan`、`vps setup`、`vps item`、`vps firewall`、`vps ssh`、`vps port`、`vps check`、`vps records`、`vps rollback`、`vps uninstall`、`vps reboot`。

## 怎样开始

用 root 登录 VPS（或先执行 `sudo -i`），运行这一行：

```bash
curl -fsSLO https://raw.githubusercontent.com/ehrenfelssotiris553-ops/vps-stable-optimizer/main/install.sh && bash install.sh
```

安装器会下载主脚本，用内置的 SHA-256 核对无误后才安装，然后打开菜单。安装器只安装菜单工具，不改系统设置；以后输入 `vps` 就能打开菜单。

- **没有 curl 的系统**，用 wget：

  ```bash
  wget -qO install.sh https://raw.githubusercontent.com/ehrenfelssotiris553-ops/vps-stable-optimizer/main/install.sh && bash install.sh
  ```

- **连不上 GitHub 时**（国内机房的 VPS 常见），手动上传：把 `install.sh` 和 `vps-stable-opt-v2.6.0.sh` 上传到 VPS 的同一个目录，在该目录运行：

  ```bash
  bash install.sh --local-file ./vps-stable-opt-v2.6.0.sh
  ```

- **刚发布新版的几分钟内**，GitHub 的缓存可能让安装器报「SHA-256 校验失败」。这是校验在保护你，不会装上不一致的版本；等 5 分钟再装即可。
- **更新到新版本**：在已经装过的机器上再运行一次上面的安装命令。安装器会原地替换主脚本，运行记录、配置备份和回退资料都保留；如果已安装的主脚本被手动改过，会停下来，不覆盖。

建议的使用顺序：

1. 在服务商控制台给机器拍一个快照。
2. 输入 `tmux new -s vps` 进入 tmux（没有就先装：`apt-get install tmux`）。这样 SSH 断线时脚本不会中断，重新登录后输入 `tmux attach -t vps` 就能回来。
3. 输入 `vps`，选 1 体检，看处理计划。
4. 选 2 一键开荒。不想逐项考虑时，在「使用推荐设置吗？」直接回车。
5. 按提示重启（以后需要重启时，也可以在菜单里选 11）。
6. 重新登录后输入 `vps`，选 7 做开荒验收。
7. 以后想单独开启或关闭某一项，选 3 单项设置，不用重跑整个开荒。

不想安装也可以直接运行 `bash vps-stable-opt-v2.6.0.sh`；这种情况下，你上传的副本不会被菜单里的卸载删除。

## 一键开荒的步骤

所有选择在第 2、3 步一次问完，之后自动执行，期间不需要操作。最后的 SSH 加固和防火墙确认需要你在场（大约 5 分钟），开始前会响铃提醒。

新机第一次开机后，系统通常会先自动更新几分钟。遇到这种情况，脚本会显示“等它结束后继续”并自动等待（最多 10 分钟），不会报错退出。

| 顺序 | 步骤 | 说明 |
| --- | --- | --- |
| 1 | 时间同步 | 最先做：系统时间偏差几天，软件更新就会因签名“尚未生效”而失败 |
| 2 | 软件索引与升级计划 | 模拟升级并标出新内核；询问是否使用推荐设置，不用时再分别问是否升级、是否开启自动安全更新 |
| 3 | 开荒选项 | 用推荐设置时只问 SSH 加固和 80/443；否则一次问完：常用工具、vnStat、旧内核清理、自动重启时间、ZRAM、内核安全参数、主机名修复、时区、SSH 加固、80/443、Fail2ban 白名单 |
| 4 | ZRAM | 内存低于 2GiB 且没有 Swap 时自动配约一半内存；2GiB 以上可选配约 1/4 内存 |
| 5 | 系统升级与组件安装 | `apt-get upgrade --with-new-pkgs`：内核更新不会被漏掉，不删包，不跨大版本；可选清理旧内核 |
| 6 | BBR | 已有其他 TCP 或队列策略就保留，不换内核 |
| 7 | 内核网络安全参数 | 可选：不接受 ICMP 重定向和源路由、开启 SYN Cookies 等；不碰 IP 转发，不影响 Docker、WireGuard、代理 |
| 8–10 | 日志限制、TRIM、自动安全更新 | 只在条件满足时处理，已有配置不覆盖 |
| 11 | 自动重启时间 | 只有你填了时间才设置：自动安全更新需要重启时，每天在这个时间重启 |
| 12 | 时区 | 可选：列出常用时区，输入编号或时区名；直接回车保持不变 |
| 13 | 主机名解析 | 主机名无法解析时可选在 `/etc/hosts` 补上 |
| 14 | SSH 登录加固 | 可选，详见下文 |
| 15 | 防火墙 | 放行 SSH；80/443 按你的选择；有公网 IPv6 却没开 IPv6 防护时会询问；新开 SSH 窗口能登录才保留（登录成功自动确认）；保留后设为开机自动加载 |
| 16 | Fail2ban | 防火墙确认生效后才配置，只封 SSH 端口；可选把当前 IP 加白名单 |
| — | 验收与重启 | 结束时逐项核对一遍；需要重启时会问「现在重启吗？」，回答 `y` 才重启 |

## 推荐设置

一键开荒在列出升级清单后会问「使用推荐设置吗？ [Y/n]」，直接回车就是使用。推荐设置包括：

- 升级系统（有可升级的软件包时）；
- 开启自动安全更新（不自动重启整机）；
- 安装常用工具：curl、wget、ca-certificates、vim、htop、unzip、lsof、tmux；
- 启用内核网络安全参数；
- 升级后清理不再需要的旧内核（保留正在运行的和最新的内核）；
- 主机名无法解析时，在 `/etc/hosts` 补上。

不在推荐设置里、保持不变的：vnStat、ZRAM（内存不到 2GiB 且没有 Swap 时仍会自动配）、自动重启时间、时区、Fail2ban 白名单。BBR、日志限制、TRIM、时间同步本来就是条件满足时自动处理。

SSH 加固和防火墙放行 80/443 不在推荐设置里，每次都会单独问你。以后想改其中任何一项，用菜单 3「单项设置」。

## 单项设置（`vps item`）

列出每一项和它现在的状态，选一项就能单独开启或关闭，不用重跑整个开荒：

| 项目 | 可以做什么 |
| --- | --- |
| 系统升级、清理旧内核 | 立即执行一次（先模拟并列出清单，再问你） |
| 自动安全更新、BBR、内核网络安全参数、ZRAM、日志空间限制、定期 TRIM、时间同步、主机名解析 | 开启；或关闭（撤销本工具的修改） |
| 更新后自动重启 | 设置每天的重启时间；或取消 |
| 时区 | 修改；或恢复成原来的时区 |
| 常用工具、vnStat | 安装；或卸载（只卸载本工具装的，先模拟） |
| 防火墙 | 开启（要新开 SSH 窗口确认）；临时关闭；撤销本工具的防火墙设置 |
| Fail2ban | 开启（需要防火墙已开启）；或关闭 |
| SSH 登录加固 | 加固；或撤销（恢复密码和 root 登录） |
| 端口管理 | 进入端口管理 |

- **关闭只撤销本工具的修改**：系统原来就有的设置不动。本工具没有改过的项目，会告诉你“本工具没有改过”，不做任何事。
- **临时关闭防火墙**：规则都保留，以后在单项设置里选「开启」就恢复。撤销则会删掉本工具加的规则。
- **你自己手动改过的项目**（例如手动执行过 `ufw disable`）：一键开荒和单项设置都照常执行，不会因此跳过；以后撤销时，一律恢复成本工具第一次运行前的样子。
- 单项设置同样会先备份，记录写进操作记录；只有这次做了系统升级、需要重启时，结束后才会问你。

只会在当前大版本内升级，不会从 Debian 12 升到 13。软件源里写的是 `stable` 这类别名时会被拦下，并告诉你怎么改成版本代号。Debian 云镜像的软件源写成 `mirror+file:///etc/apt/mirrors/…` 时，会读取那个镜像列表，里面全是官方地址就按官方源检查。

## SSH 登录加固

1. **管理员账户（推荐）**：用 root 登录时，可以新建一个普通管理员账户（加入 sudo 组并设置密码）。已经在用 sudo 账户登录时，可以直接选择禁止 root 直接登录。
2. **公钥登录被服务商关掉时先开启**：有些镜像在 `/etc/ssh/sshd_config` 里写了 `PubkeyAuthentication no`。这时会显示是哪个文件哪一行，并问你要不要先开启公钥登录：新增 `/etc/ssh/sshd_config.d/00-vps-stable-pubkey.conf`（原配置文件不改），只是多一种登录方式，密码登录照常可用。撤销时会删掉这个文件，公钥登录回到原来的关闭状态。
3. **导入公钥**：公钥以目标账户自己的身份写入，并且会先检查家目录的归属和权限。还没有密钥时，会告诉你怎么在自己电脑上生成（`ssh-keygen -t ed25519`）。
4. **确认密钥登录**：新开一个窗口用密钥登录。如果要禁止 root 登录，还要在那个窗口里运行一次 `sudo true`。脚本会在系统日志里确认这两件事都发生过；找不到记录时，会分别问你是否确定已经成功（回答 `y`）。sudo 没有确认时，只关闭密码登录，不禁止 root 登录。
5. **控制台登录检查**：服务商的 VNC 控制台只能用密码登录。如果目标账户和 root 都没有可用的密码，会提示你当场设置一个；不设置就要输入 `NOCONSOLE` 才能继续。
6. **写入配置**：写入 `/etc/ssh/sshd_config.d/01-vps-stable-keyonly.conf`，包括：
   - 关闭密码登录；
   - 可选禁止 root 登录；
   - `MaxAuthTries 4`；
   - `LoginGraceTime 30`；
   - `X11Forwarding no`；
   - `ClientAliveInterval 300` / `ClientAliveCountMax 2`：断开失效连接，也减少空闲断线。

   写入后会检查每一项确实生效；被更早的配置覆盖的，会自动撤销并告诉你是哪一项。
7. **防失联确认**：先启用自动撤销计时器，再请你新开一个窗口用密钥登录。登录成功后脚本会自动确认；没有自动确认时，回到原来的窗口输入 `CONNECTED`。180 秒内没有确认就恢复原来的设置；脚本万一中断，240 秒时计时器也会自动恢复。

不改 SSH 端口。导入的公钥和新建的账户在回退时都会保留。

## 端口管理

菜单选 6，或者直接用命令：

```bash
vps port open 8080
```

```bash
vps port open 443-600 udp
```

```bash
vps port open 3306 tcp from 203.0.113.5
```

```bash
vps port close 8080
```

```bash
vps port list
```

- **端口写法**：支持 `8080`、`443-600`、`8080,9000-9100`。命令行不写协议时默认 both（TCP+UDP）。
- **自动拒绝**：会拒绝一次放行全部端口，也会拒绝关闭 SSH 端口或包含它的端口段。
- **只关一种协议**：不写协议的规则（例如 `ufw allow 18081`）同时放行 TCP 和 UDP。只关其中一种时，会先单独放行另一种，再删除原来那条，另一种协议不受影响；单独放行失败时原规则保持不变。所以 `vps port close 22 udp` 只关 UDP，SSH 的 TCP 照常放行。
- **高危端口提醒**：数据库、管理类端口（MySQL、Redis、MongoDB、Docker API、RDP 等）要对所有人开放时，会提醒并再确认一次，并建议改成只允许你自己的 IP。
- **大范围确认**：一次放行超过 1000 个端口时会再确认一次。
- **Docker**：检测到 Docker 时会提醒：用 `-p` 发布的容器端口会绕过 UFW。
- **回退时保留**：用端口管理放行的业务端口，在撤销设置时会保留。

## 重启服务器（`vps reboot`）

菜单选 11，或者直接用命令 `vps reboot`：

- **先说明需不需要重启**：装了新内核还没生效、系统提示需要重启，或者目前不需要重启。
- **这两种情况下不会重启**：
  - 防火墙或 SSH 加固的防失联确认还没结束：重启会让保护计时器失效，没确认的修改就会被永久保留。先回到那个窗口完成确认，或者等计时结束。
  - 有程序正在安装或更新软件：会先等它结束（最多 10 分钟），还没结束就不重启，免得损坏软件包。
- **回答 `y` 才重启**：所有 SSH 连接会断开，通常一两分钟后可以重新登录。重启后输入 `vps` 选 7 做开荒验收。

## 开荒验收（`vps check`）

脚本会记下每个模块在开荒时的结果，验收时逐项核对：

- **✅ 生效**：按预期在工作。
- **❌ 未生效**：做了，但现在没起作用，会说明原因和处理方法。
- **➖ 未处理**：按计划本来就没做，或者后来撤销了（会写明「已撤销」）。
- **❓ 无法确认**：缺少条件判断，例如内核或容器读不到某个参数。

验收会核对开荒做过的每个模块：
- 系统：内核、BBR、内核安全参数、ZRAM、时间同步、日志限制、TRIM；
- 更新：自动安全更新、自动重启时间；
- 工具和设置：常用工具、流量统计、时区、主机名；
- 安全：SSH（包括 root 是否真的不能直接登录）、防火墙、Fail2ban。

其中几项看得更严：
- 防火墙除了现在开着，还要设为开机自动加载（`ufw.service`），否则重启后就没有防火墙；
- Fail2ban 的封禁要靠防火墙执行，防火墙没运行就算未生效；
- 系统盘不支持 TRIM（`lsblk` 的 DISC-MAX 为 0）时显示为未处理，不算生效。

有项目「未生效」时，`vps check` 的退出码是 3（没有未生效项目时是 0），方便脚本判断。

此外还会检查：
- 开荒后是否重启过；
- 当前 SSH 连接实际用的拥塞算法；
- 失败的服务、DNS 解析；
- 有没有装 Docker。

报告保存在 `/var/log/vps-stable-opt/`，只保留最近 10 份。可选的 Fail2ban 实弹测试，用专门留给测试的 IP 地址模拟封禁再解封，不需要你去登录。

## 体检里新增的安全检查

- **公钥清单**：列出 root 和所有普通账户的 `authorized_keys` 公钥指纹，帮你发现镜像或服务商预置的公钥。
- **Docker**：检测到 Docker 时提醒容器端口会绕过防火墙。
- **软件包中断**：软件包处于中断状态时，告诉你用 `dpkg --configure -a` 修复。

## 怎样回答问题

大多数问题用 `y` 或回车回答：

- **`[Y/n]`**：直接回车表示「做」。用于推荐的、风险低的选择：使用推荐设置、系统升级、自动安全更新、内核网络安全参数、主机名修复。
- **`[y/N]`**：直接回车表示「不做」，要输入 `y` 才做。用于开始修改、关闭端口、重启、撤销、卸载软件包等。

只有三处要输入单词。提示里会写出要输入什么，区分大小写；输成小写时会提醒你要用大写：

| 单词 | 什么时候要输 |
| --- | --- |
| `CONNECTED` | 开启防火墙或加固 SSH 后，新开一个 SSH 窗口登录：登录成功通常会自动确认，不用输入。没有自动确认时，回到**原来的窗口**输入（新窗口里不用输入任何东西）。输错或输成小写会提示你重输；新窗口登录失败就在原窗口输入 `n`，立即恢复；180 秒内没有确认，也会自动恢复原来的设置。 |
| `NOCONSOLE` | 没有控制台密码时，仍要关闭 SSH 密码登录（不推荐：SSH 出问题时控制台也进不去）。 |
| `UNINSTALL` | 卸载本工具，会删除全部记录和备份。 |

## 撤销设置与卸载

| 操作 | 工具、记录、备份 | 软件 | 优化配置和效果 |
| --- | --- | --- | --- |
| 撤销本工具的设置 | 保留 | 保留；可选卸载本工具新装的包 | 恢复成本工具第一次运行前的样子（例外见下文） |
| 卸载本工具 | 删除 | 保留 | 保留 |

菜单选 9（或 `vps rollback`）会先列出和本工具第一次运行前不一样的项目，再让你选：

- **1. 全部撤销**：按安全的顺序（先 Fail2ban，再防火墙，再 SSH 和其他设置）全部恢复，最后可选卸载本工具新装的软件包。
- **2. 只撤销某一项**：从列表里选一项，例如只撤销 BBR，其他设置不动。

单项设置里的「关闭」和这里的「只撤销某一项」是同一套逻辑。

撤销设置时：

- **一律恢复原样**：本工具记录过的设置，撤销时都恢复成本工具第一次运行前的样子，不管中间是谁改的——你后来手动改过的也一样。
- **只放宽访问**：只会关闭防火墙、恢复密码和 root 登录，不会把你锁在外面。关闭防火墙后会提醒你，所有监听的端口都已直接暴露。
- **防火墙按规则回退**：只删除本工具自己加的规则，再恢复默认策略、IPv6 开关和防火墙开关。你后来放行的端口、Fail2ban 的封禁记录都不受影响。
- **Fail2ban**：先解除本工具封禁的 IP，再删除本工具的规则和动作文件；原来就有的 Fail2ban 会按它自己的配置重新加载。
- **内核安全参数**：删除配置文件，并把运行中的参数恢复为原来的值。
- **`/etc/hosts`**：这个文件你和系统都会改，所以只删除本工具加的那一行主机名，其他行不动。
- **其他设置**：BBR、ZRAM、日志限制、自动更新、自动重启时间、时间同步、TRIM、时区也都恢复成原来的样子。
- **卸载软件包需模拟确认**：卸载本工具新装的软件包前会先模拟；会连带删除原来就有的软件时不执行。
- **撤销不了的部分**：
  - 系统升级（软件包不会降回旧版本）、新内核、已经清理的旧内核；
  - 已执行的 TRIM 和已经校准的系统时间（时间同步的开关本身会恢复）。
- **有意保留的部分**：
  - 导入的 SSH 公钥、新建的管理员账户和它的密码（删掉可能把你锁在外面）；
  - 用端口管理放行的业务端口；
  - 新装的软件包（可选卸载，只卸本工具装的；用 remove 不是 purge，配置文件会留在 `/etc`）；
  - 防火墙不会被自动重新打开：如果它原来开着、后来被关掉了，撤销会提示你手动执行 `ufw enable`。

  需要整机还原时，请用服务商快照。

**卸载会删除备份。** 删除后，即使重新安装也无法可靠回退。需要的话，先把备份保存到自己的电脑。

## Ubuntu 26.04 说明

Ubuntu 26.04 LTS（resolute，标准维护到 2031 年 5 月）默认做了几处改动，本工具都已考虑：

- **Rust 版 coreutils（uutils）**：`ls`、`stat`、`sort` 等基础命令换成了 Rust 实现。本工具每次启动都会先做一次基础命令自检（`mktemp`、`install`、`stat`、`sort -V`、`sha256sum`、`df`、`readlink`、`cp -p`、`mv` 等）。行为和预期不一致时直接停止，不做任何修改，并提示可以用 `apt install coreutils-from-gnu` 换回 GNU 版本。
- **sudo-rs**：默认 sudo 换成了 Rust 实现。SSH 加固时，脚本会在系统日志里找 sudo 的记录；如果日志格式不同而找不到，会改为问你是否确定 sudo 可用。
- **chrony**：默认用 chrony 做时间同步。已有可用的时间同步时，本工具保持不变，不会再装 systemd-timesyncd。

这几处还需要在真实的 26.04 机器上确认，见 `V2.6.0-优化记录.md`。

## 固定目录

| 内容 | 位置 |
| --- | --- |
| 调用命令 | `/usr/local/bin/vps` |
| 主脚本 | `/usr/local/lib/vps-stable-opt/vps-stable-opt.sh` |
| 运行状态、回退基线（`restore-v2`）、开荒结果（`modules`） | `/var/lib/vps-stable-opt/` |
| 每次运行的配置备份 | `/var/backups/vps-stable-opt/` |
| 运行日志（开荒保留最近 9 份，端口操作单独保留 20 份）、验收报告 | `/var/log/vps-stable-opt/` |

数据目录必须归 root 所有，路径里不能有符号链接，其他用户不能写入，不满足时会直接停止。已经有别的 `vps` 命令时，安装也会停止，避免覆盖。

## 发布新版本

仓库地址：https://github.com/ehrenfelssotiris553-ops/vps-stable-optimizer

`install.sh` 里的 `RELEASE_BASE_URL` 指向本仓库 `main` 分支的原始文件；换仓库或分支时要同步修改。已经装过的机器重新运行安装命令就会原地更新到新版本。

安装器会用内嵌的 SHA-256 核对主脚本，所以每次修改主脚本后都要：

1. 重新计算主脚本的 SHA-256，填进 `install.sh` 里的 `EXPECTED_SHA256`。
2. 重新生成 `SHA256SUMS`：

   ```bash
   sha256sum .gitattributes README.md V2.6.0-优化记录.md install.sh tests/*.sh vps-stable-opt-v2.6.0.sh > SHA256SUMS
   ```

3. 提交并推送。主脚本和 `install.sh` 必须在同一次推送里更新，否则新装的机器会校验失败（安装会停止，不会装错）。
